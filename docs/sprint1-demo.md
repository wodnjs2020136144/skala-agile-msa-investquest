# Sprint1 리뷰 데모 스크립트

프런트엔드 Walking Skeleton 시연용. 화면을 띄워 놓고 위에서부터 그대로 따라간다.
전체 5분 안쪽.

> **전제**: 백엔드 산출물이 아직 없다. 목 데이터 모드로 시연한다.
> 왜 그래도 되는지는 아래 "먼저 말할 것"에 있다.

---

## 0. 사전 준비 (데모 시작 전)

```bash
cd vue-frontend
grep VITE_USE_MOCK .env      # VITE_USE_MOCK=true 여야 한다
npm install                  # 처음 한 번만
npm run dev                  # http://localhost:3000
```

브라우저 준비:

- **시크릿 창**으로 연다. `sessionStorage`에 이전 로그인이 남아 있으면
  비로그인 홈부터 보여 주는 1번 단계를 건너뛰게 된다.
- DevTools를 **Network 탭**으로 열어 둔다. 마지막에 쓴다.
- 창 너비는 데스크톱으로 시작한다. 6번에서 390px로 줄인다.

## 1. 먼저 말할 것 (30초)

> "백엔드가 아직 도착하지 않아서 목 데이터로 시연합니다.
> 그런데 **화면이 임시가 아니라 연결만 안 된 상태**입니다.
> `.env`의 플래그 한 줄(`VITE_USE_MOCK=false`)을 끄면 OAuth2 로그인과
> 실제 API Gateway로 그대로 넘어갑니다. OAuth2 코드는 한 줄도 지우지 않았습니다."

> "등장하는 종목 6개는 **실존 상장사**입니다. 다만 **제시 가격과 3일 뒤 결과는 전부 가상**이고
> 실제 시세가 아닙니다."

### 6-1. 배분 화면에서 반드시 할 동작

성향 신호가 수집되는 걸 마지막에 보여 주려면 **배분을 최소 3번은 바꾼다.**

1. 가온반도체(IT·고위험)에 크게 넣는다
2. 다시 줄인다 ← 이 "마음을 바꾼 행동"이 지표가 된다
3. 한별금융지주(금융·저위험)·들안식품에 나눠 넣는다
4. **전액을 쓰지 않고 현금을 남긴다** ← 현금 비중이 성향 축이다

말할 것:

> "현금을 남기는 것도 유효한 선택으로 뒀습니다. 전액 투자를 강제하면
> 안정 성향인 사람의 신호가 사라집니다."

## 4. 성향 신호가 이미 수집되고 있다 (1분) — Sprint2로 넘기는 자리

확정까지 마친 뒤 DevTools **Console**에 붙여 넣는다.
(`$pinia`는 전역에 없다. Vue 앱 인스턴스를 거쳐야 한다.)

```js
document.querySelector('#app').__vue_app__
  .config.globalProperties.$pinia
  .state.value.game.events.at(-1)
```

`INVESTMENT_SUBMITTED` 이벤트에 지표 7종이 들어 있다. 실제 출력 예시:

```js
{
  type: 'INVESTMENT_SUBMITTED', at: '...',
  totalAmount: 5000, cashBalance: 5000,
  cashWeight: 50, concentrationRatio: 50, highRiskRatio: 50,
  sectorWeights: { IT: 50, 금융: 50 },
  stockCount: 2, changeCount: 3, decisionSeconds: 18
}
```

| 지표 | 분모 | 초안 §7의 해석 |
|---|---|---|
| `cashWeight` | 초기자금 | 현금 비중 — 안정성 선호 |
| `concentrationRatio` | **투자금** | 한 종목 최대 비중 — 집중 vs 분산 |
| `highRiskRatio` | **투자금** | 고변동성 종목 비중 — 위험 감수 |
| `sectorWeights` | **투자금** | 업종별 비중 — 관심 산업·테마 |
| `stockCount` | — | 선택 종목 수 — 분산 수준 |
| `changeCount` | — | 선택을 바꾼 횟수 — 신중함 / 판단 변동성 |
| `decisionSeconds` | — | 게임 시작부터 확정까지 걸린 시간 — 즉흥형 vs 숙고형 |

> **분모가 두 계열이다.** 배분 화면에 보이는 비중(종목 25% · 현금 50%)은
> **초기자금 기준**이라 현금을 포함해 합이 100%가 된다.
> 위 성향 지표 3종은 **투자금 기준**이라 "투자한 5,000원을 어떻게 나눴나"를 본다.
> 같은 배분에서 종목 하나가 화면에는 25%, 지표에는 50%로 나오는 이유다.
> 성향 분석 서비스가 투자금 기준으로 계산하므로 거기에 맞췄다.

질문이 나오면: "현금을 얼마나 남겼는지는 `cashWeight`가 따로 답합니다.
투자금 기준 지표는 그 위에서 '쓴 돈의 성격'만 봅니다."

> "Sprint2의 AI 분석 **입력**은 이미 준비돼 있습니다.
> 어떤 방식으로 분석할지(규칙 기반이냐 LLM이냐)는 아직 정하지 않았지만,
> **어느 쪽으로 가도 입력은 같기 때문에** 수집을 먼저 시작했습니다."

> "특히 `changeCount`와 `decisionSeconds`는 **DB로는 절대 복원할 수 없습니다.**
> 최종 선택만 저장되니까요. 화면에서 관찰하지 않으면 영영 없는 데이터입니다."

⚠️ 지금은 **수집만 하고 서버로 보내지 않는다.** 전송 여부는 미결 안건이고
받을 백엔드 필드도 아직 없다. 물어보면 그렇게 답한다.

## 5. 마무리 — 다음 스프린트에 필요한 것

BE에 요청할 것을 이 자리에서 말한다:

- `EnrollRequest`에 `investmentAmount` · `participationId` 추가
- 시나리오·제시 종목 조회 경로 확정
  (`/api/courses/scenarios/{id}`, `/api/courses/offered` — 전부 **제안**이다)
- **새 prefix는 만들 수 없다.** API Gateway가 소스 없는 완성 이미지라
  `/api/{users,courses,enrollments,payments,recommend}` 5개 밖은 404다

팀 결정이 필요한 것:

- 섹터명 6종을 `courses.category` enum에 어떻게 반영할지
- 행동 이벤트를 서버로 보낼지, 보낸다면 어느 필드로
- 성향 분석 방식 (규칙 기반 / LLM / 규칙+LLM 설명문)

## 부록 — 목 모드에서 안 보이는 것

헤더의 **강의 · 내 학습 · 마이페이지** 링크는 목 모드에서 내려가 있다.
강사 배포 템플릿 화면이라 목 분기가 없고, 누르면 실제 백엔드(`localhost:8080`)를
호출하다 실패해 에러 화면이 뜨기 때문이다.

**파일과 라우트는 지우지 않았다.** `VITE_USE_MOCK=false`로 두면 그대로 돌아온다.
Sprint2의 결과·리워드·추천 화면이 이 자리에서 출발한다.

데모 중 "왜 메뉴가 이것뿐이냐"는 질문이 나오면 위 두 문단으로 답한다.

## 안내 문구 (질문이 나오면)

- **실존 종목명**을 쓰지만 **제시 가격과 결과는 가상**이며 실제 시세가 아니다.
- 모의 투자이며 실제 매매가 이루어지지 않는다.
- 게임 결과는 참고용 보조 정보이며 **공식 투자자 성향 진단을 대체하지 않는다.**
