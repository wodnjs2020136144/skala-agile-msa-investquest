# Sprint 2 게임·리워드 정책

## 확정 규칙

- 최초 가상 투자금: `10,000,000원`
- 게임 결과 산정 기간: 투자 확정 후 `3일`
- 사용자 노출 문구: `참여 리워드 최대 1만원`
- 수익률이 양수이면: `10,000P`
- 손실 또는 수익률 0%이면: `5,000P`
- 지급 포인트는 다시 `3일` 동안 투자한 후 출금할 수 있다.
- 종목의 위험도 값은 성향 분석 입력으로 사용하지만 프론트 화면에는 표시하지 않는다.
- 주문 입력 단위는 원이 아니라 정수 `주`이며 소수점 주식은 허용하지 않는다.
- 25%·50%·최대 선택 시 해당 예산으로 살 수 있는 최대 정수 주를 계산하고 잔액은 현금으로 둔다.
- 종목 코드는 사용하거나 화면에 표시하지 않는다.

## 기존 데이터 최대 재사용

이번 정책 변경으로 신규 테이블을 추가하지 않는다.

| 기존 데이터 | 게임 도메인에서의 사용 |
|---|---|
| `courses` | 가상 종목과 기준 가격 |
| `enrollments` | 사용자가 확정한 종목별 투자 주문 |
| `payments.amount` | 지급할 리워드 포인트 |
| `payments.status=PENDING` | 포인트 재투자 또는 출금 대기 |
| `payments.status=COMPLETED` | 3일 재투자 조건 완료, 출금 가능 |
| `payments.created_at` | 리워드 지급·재투자 시작 시각 |
| `payments.updated_at` | 재투자 완료 시각 |
| 프론트 `events` | 시작·시나리오 조회·배분 수정·투자 확정 행동 로그 |

현재 프론트 행동 이벤트는 Pinia 메모리에 수집한다. 백엔드 연동 시 이벤트 타입과 payload를
그대로 전달하여 기존 이벤트 구조를 유지하고, 별도 행동 유형을 불필요하게 늘리지 않는다.

## 결과 이벤트 처리 방향

1. 3일 후 결과 수익률을 계산한다.
2. 수익률이 `0보다 크면 10,000P`, 그 외에는 `5,000P`를 결정한다.
3. `POST /api/payments/internal/rewards`로 기존 Payment에 `PENDING` 리워드를 기록한다.
4. 리워드 포인트를 3일 재투자한다.
5. `GET /api/payments/internal/rewards/{paymentId}`로 재투자 종료일과 출금 가능 여부를 확인한다.

실제 외부 출금 실행과 예약 작업은 현재 Sprint 2 범위 밖이다. 리워드는 transaction_id의
`REWARD-` 접두어로 일반 결제와 구분하며 신규 테이블이나 컬럼을 추가하지 않는다.
